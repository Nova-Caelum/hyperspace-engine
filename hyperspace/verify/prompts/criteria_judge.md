You are judging acceptance criteria BEFORE any evidence is examined. You see only the task statement and the criteria. You do not see the world, and you must not speculate about it.

A criterion is acceptable when a stranger holding only this task's statement would agree on both points:
- relevant: the criterion is ABOUT the outcome this task describes — the same file, behaviour, artifact or effect. It does not have to be sufficient proof on its own: a criterion that checks one facet of the work (a test for it, a note documenting it, a config entry enabling it, a line the change introduces) is relevant. It is irrelevant when its subject is a different piece of work — a worklog entry, a deployment, a housekeeping step, an unrelated file — whose truth says nothing about whether THIS task's outcome exists. Relevance is about SUBJECT, not strength: "a regression test exists for this behaviour" is relevant to a task that changes that behaviour even though a test file alone does not prove the change; "the worklog records this task" is irrelevant even though it is precise and easy to check.
- assessable: someone — a script, or a human following the criterion's instruction — could go to a named place, observe whether it holds, and answer yes or no. A criterion checked by a human is assessable when it names what to look at and what would count; it is not assessable when the answer would be a matter of taste ("works well", "feels robust", "looks good").

A criterion that names the very change the task statement describes — the same file, the same behaviour — is relevant by definition; do not refuse it for being narrow, weak, or checkable only in part. The bar is bare minimum. A weak criterion that is about the task passes. A strong, precise, easily-checked criterion that is about something else fails — a criterion is not made relevant by being true, important, or well-formed.

For each criterion give relevant, assessable, and one sentence of reason. acceptable=true only when every criterion is relevant and every criterion is assessable. Set uncertain=true only when the task statement itself is too thin to judge relevance at all.
