# Reference — command-line interfaces

> Generated by `docs/reference/generate.py` from source. Do not edit by hand —
> change the code, then run `python docs/reference/generate.py`. CI fails when
> this file and the code disagree.

Two command surfaces. The **engine scripts** in `bin/` run the loop; inside a session the skills
call them as `.hyperspace/env/bin/python "${CLAUDE_PLUGIN_ROOT}/bin/<script>.py" …`. The
**`hyperspace` command** is installed into the project's `.hyperspace/env` by the setup skill and
runs the store, the local web server and the health check.

### `gate-pass`

Consult the node's exit check, then freeze the artifacts a node just produced.

| Argument | Required | Notes |
|---|---|---|
| `path` | yes |  |
| `--node` | yes |  |
| `--artifact` | no | zero or more artifact file paths (none needed when the gate refuses) — nargs `*` |
| `--by` | yes | identity that froze these artifacts |
| `--workplan` | no | T4.8: path to the N3 workplan JSON; required when --node executing |
| `--reconciliation` | no | T4.9 (loop-ending-executing-live-done): path to the run's reconciliation artifact naming every workplan row's disposition (done/deferred/archived/live-test); required when --node executing |
| `--verifications-dir` | no | T4.8: verifier run-files directory (default: <run-dir>/misc/verifications) |

| `--tests` | no | T4.3: path to N1's tests.json; required when --node understanding |
| `--decision` | no | T4.4: path to N2's mapping.json; required when --node deciding |
| `--plan` | no | T4.5: path to N3's Plan.md with task_ids backfilled by the uploader; required when --node specifying |

## `hyperspace` — the store, the web server, the health check

`hyperspace <command> …` · `hyperspace --version`

### `hyperspace init`

`hyperspace init [--dir <project-dir>] [--provision [--judge NAME] [--port N] [--user NAME]]` — creates `<dir>/.hyperspace/graph.db`, and with `--provision` also provisions the isolated environment, resolves the judge (probed unless `--judge` names one explicitly), writes `.hyperspace/config.toml`, and writes the launcher — the setup skill's non-interactive path (brief step 2f), nothing prompted.

| Argument | Required | Notes |
|---|---|---|
| `--dir` | no | default `.` |
| `--provision` | no |  |
| `--judge` | no | choices: `openrouter`, `anthropic`, `claude-code`, `codex`, `none` |
| `--port` | no |  |
| `--user` | no |  |

### `hyperspace serve`

`hyperspace serve [--port N] [--open] [--dir <project-dir>]` — binds the loopback door and blocks in the foreground until Ctrl-C.

| Argument | Required | Notes |
|---|---|---|
| `--port` | no |  |
| `--open` | no |  |
| `--dir` | no | default `.` |

### `hyperspace doctor`

`hyperspace doctor [--dir <project-dir>]` — re-runs the setup skill's check phase (python, env, store, config/judge, door port free-or-ours) and prints one OK/FAIL line per check; exits 0 only when every check reads OK.

| Argument | Required | Notes |
|---|---|---|
| `--dir` | no | default `.` |
